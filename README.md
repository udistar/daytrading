# 초단타 데이트레이딩 v0 (모의투자)

장 시작 직후 급등한 국내 주식을 규칙대로 나눠 사고, 손절·익절·시간 청산으로 파는 Windows용 프로그램입니다. 매수·매도 판단은 정해 둔 숫자 규칙만 사용합니다. 인공지능이 주문을 결정하지 않습니다.

이 버전은 **실전 매매 프로그램이 아닙니다.** 실전 주소로는 접속하지 못하게 잠가 두었습니다. 키 없이도 가짜 시세와 가짜 증권사로 아침 매매 전체를 돌려 볼 수 있습니다. 실제 주문 품질은 나중에 모의투자 계좌로 확인해야 합니다.

## 화면에서 볼 수 있는 것

- 오늘 손익과, 하루 손실 한도까지 남은 금액
- 종목별 가격이 오르는지 내리는지
- 보유, 주문, 체결
- 진입·추가 매수·거절이 적힌 흐름
- **매매 중지**: 새로 사는 것만 막고, 이미 가진 종목의 손절·청산은 계속합니다
- **긴급 전체 청산**: 가진 종목을 시장가로 모두 팔고 오늘은 더 사지 않습니다
- **설정**: 아래 숫자는 전부 화면에서 바꿀 수 있습니다. 저장해야 파일에 남고, 바꾼 내용은 이력이 쌓입니다

기본 숫자는 승인된 명세와 같습니다. 예: 시작 금액 5,000만 원, 하루 손실 한도 100만 원, 손실 70만 원부터 신규 매수 중단, 종목당 1,000만 원·최대 5번, 동시에 5종목, 09:05~09:40 신규 진입, 09:45까지 추가 매수, 09:47 절반 정리, 09:49:30 잔량 시장가, 09:50 이후 매수 금지.

## 설치

1. [Python 3.11 이상](https://www.python.org/downloads/windows/)을 설치합니다. 설치 화면에서 **Add python.exe to PATH** 를 켜 주세요. `py` 실행기가 있으면 그대로 써도 됩니다.
2. 이 폴더에서 `run.bat` 을 더블클릭합니다. `py -3.14` 가 되면 그 버전을 쓰고, 없으면 `py -3` 으로 넘어갑니다. 처음 한 번은 화면 라이브러리를 설치한 뒤 프로그램이 열립니다.

명령으로 실행할 때는 폴더에서 다음을 입력합니다.

```bat
py -3 -m pip install -r requirements.txt
set PYTHONPATH=src
py -3 -m daytrading
```

키 없이 아침 매매를 재현하려면 `run_sim.bat` 을 실행하거나 아래에 `--sim` 을 붙입니다.

```bat
set PYTHONPATH=src
py -3 -m daytrading --sim
```

시뮬을 돌리면 체결 내역과 손익 요약이 나옵니다. 화면의 **시뮬레이션 실행** 버튼도 같은 일을 하고, 표에 방향·보유·주문·체결을 채웁니다. 방향 색은 국내 시세와 같이 오르면 빨간색, 내리면 파란색입니다. 시뮬레이션은 시나리오가 여러 개라 손익을 하나로 합쳐 보여 주지 않습니다.

## 모의투자 서버에 연결하기

키를 넣은 뒤, 주문을 내기 전에 접속만 확인합니다. 이 명령은 토큰을 받고 웹소켓으로 시세를 등록한 뒤 끝납니다. 주문 API는 호출하지 않습니다.

```bat
set PYTHONPATH=src
py -3 -m daytrading --check
```

화면의 **모의투자 연결 확인** 버튼도 같습니다.

같은 매매 규칙으로 모의투자 시세를 받아 주문까지 보내려면 아래를 실행합니다. 주문 주소는 `https://mockapi.kiwoom.com` 입니다. 실전 주소 `https://api.kiwoom.com` 은 코드에서 열리지 않습니다.

```bat
set PYTHONPATH=src
py -3 -m daytrading --paper
```

거래대금이 왜 거절되는지, 지금 시각이 진입 창 안인지 보려면 아래를 실행합니다. 주문 API는 호출하지 않습니다. 주식체결 FID 14(누적거래대금)는 공식 명세가 백만원으로 적고, 이 프로그램은 그 값을 원으로 바꿔 필터와 비교합니다.

```bat
set PYTHONPATH=src
py -3.14 -m daytrading --diagnose --home <폴더>
```

모의 계좌로 주문 경로만 확인하려면 아래를 실행합니다. `mockapi.kiwoom.com` 에만 붙고, 삼성전자 1주를 시장가로 산 뒤 체결·주문번호를 출력합니다. 평일 09:00~15:30이면 그 체결 수량만 바로 시장가로 팝니다. 실전 주소 `api.kiwoom.com` 이 접속 주소면 실행을 거부합니다.

```bat
set PYTHONPATH=src
py -3.14 -m daytrading --smoke --home <폴더>
```

주문 없이 시세만 엔진에 넣으려면 `--paper --dry-run` 을 씁니다. `--dry-run` 만 쓰면 `--check` 와 같이 접속만 확인합니다. 화면의 **모의투자 시작**은 확인을 받은 뒤 모의 서버로만 주문합니다. **매매 중지**는 새 매수를 멈추고 손절·청산은 계속합니다.

종목의 관리·ETF·상장일 정보는 `symbols_meta.csv` 가 있어야 신규 매수가 나갑니다. `--paper` 를 시작하면, 시세를 등록하기 전에 모의투자 주소 `https://mockapi.kiwoom.com` 의 종목정보 리스트(ka10099)로 그 파일을 채웁니다. 같은 날 이미 받아 두었으면 다시 부르지 않습니다. 전일종가와 시가는 실시간 체결의 등락률·시가로 채웁니다. 09:50 이후 보유가 없으면 루프를 끝내고 프로세스는 코드 0으로 빠집니다. 이 경로는 모의투자 확인용이며, 실전 매매 준비가 된 상태가 아닙니다.

## 설정을 바꾸는 방법

프로그램의 **설정** 탭에서 값을 고친 뒤 **저장**을 누릅니다. 범위를 벗어나면 저장되지 않고, 무엇이 잘못됐는지 적힙니다. **변경 이력**에서 이전 값을 볼 수 있습니다. **기본값으로**는 화면만 되돌립니다. 파일에 반영하려면 다시 저장해야 합니다.

저장 위치는 사용자 폴더의 `.daytrading\settings.json` 입니다. 탐색기 주소창에 아래를 붙여 넣으면 열립니다.

```text
%USERPROFILE%\.daytrading
```

다른 폴더를 쓰려면 환경변수 `DAYTRADING_HOME` 에 그 폴더를 지정합니다.

실전 매매 칸은 꺼진 채로 잠겨 있습니다. v0에서는 켤 수 없습니다.

## 모의투자 키를 넣는 곳

키는 코드나 이 저장소에 넣지 마세요. 둘 중 하나만 쓰면 됩니다.

- 환경변수 `KIWOOM_APP_KEY`, `KIWOOM_APP_SECRET`, `KIWOOM_ACCOUNT_NO`
- 또는 `%USERPROFILE%\.daytrading\secrets.env`

`secrets.example.env` 를 그 경로로 복사한 뒤 값을 채우면 됩니다. 환경변수에 값이 있으면 파일보다 우선합니다. 프로그램은 키 내용을 로그에 남기지 않습니다.

키움에서 받을 때 순서는 다음과 같습니다.

1. [키움 REST API](https://openapi.kiwoom.com) 오른쪽 위 **API 사용신청**. HTS 아이디가 계좌에 연결돼 있어야 합니다. 안내: [서비스 소개](https://openapi.kiwoom.com/intro), [이용안내](https://openapi.kiwoom.com/intro/serviceInfo).
2. **상시모의투자**를 따로 신청합니다. 홈페이지 > 모의투자 > 상시모의투자 > 주식. 안내: [모의투자 이용안내](https://openapi.kiwoom.com/intro/mockInvestInfo).
3. **모의투자 App Key** 는 실전 키와 다릅니다. ‘모의투자 App Key 관리’에서 받습니다. 키 파일은 **한 번만** 내려받을 수 있으니 안전한 곳에 보관하세요.
4. 이 프로그램에는 그 모의투자 키만 넣습니다.

## IP 등록

키움은 등록한 IP에서만 접속을 받습니다. 최대 10개입니다. 프로그램을 돌릴 컴퓨터의 공인 IP를 [이용안내](https://openapi.kiwoom.com/intro/serviceInfo)에 적힌 대로 등록하세요. 집 IP가 바뀌면 다시 등록해야 합니다.

## 영웅문4 조건식

조건검색을 쓰려면 Windows용 **영웅문4**에서 조건식을 먼저 저장해야 합니다. 저장한 뒤 설정 탭의 **영웅문4 조건식 일련번호**에 `0,1` 처럼 번호를 적습니다. 비워 두면 조건검색 없이 순위 조회만 사용합니다. 실시간 조건검색은 최대 10개입니다. 설명: [API 가이드](https://openapi.kiwoom.com/guide/apiguide), [유량 공지](https://openapi.kiwoom.com/board/Board0101View?seqid=49).

순위·조건검색만으로 종목의 관리·투자경고·ETF·상장일을 알 수 없습니다. 모의투자를 시작하면 ka10099로 `%USERPROFILE%\.daytrading\symbols_meta.csv` 를 만듭니다. 칸 모양은 `symbols_meta.example.csv` 와 같습니다. 공식 명세에 없는 값은 `unknown` 으로 적습니다. `unknown` 은 제외 플래그를 켜지 않습니다. 정보가 아예 없는 종목은 기본으로 신규 매수하지 않습니다. 시뮬레이션은 이 정보를 채워서 넣습니다. 거절 사유는 돌파하지 않아도 `rejections.csv` 에 남고, 같은 종목·같은 사유는 1분에 한 줄입니다.

## 주문 전에 확인할 것

- **최선집행기준 설명서**를 받지 않으면 2026-09-14부터 주문이 거부됩니다. 영웅문 HTS/MTS 팝업이나 1544-9000. [공지](https://openapi.kiwoom.com/board/Board0101View?seqid=61).
- 모의투자는 **TR 하나당 초당 1회**입니다. 프로그램 자체 호출 상한은 초당 4회이고, 청산이 신규 매수보다 먼저 나갑니다. 실전 주문·조회 초당 5회는 설정에만 저장하고 v0에서는 쓰지 않습니다. [서비스 소개](https://openapi.kiwoom.com/intro).
- 수수료 기본값은 키움 FAQ의 현금주식 0.015%(편도)이고, 매도세 기본값은 0.20%입니다. 수수료 안내 페이지는 확인되지 않았습니다. 영웅문 **[0900]** 에서 본인 계좌 요율을 보고 설정에 맞게 고치세요. [FAQ](https://www.kiwoom.com/m/domestic/stock/VStockMainView).
- **3개월** 동안 실서버에 로그인하지 않으면 API 사용이 해지됩니다. 모의 서버만 드나든 것은 접속으로 치지 않습니다.

## 시뮬레이션이 보여 주는 것

내장 시뮬은 시계를 빨리 돌려 아래를 한 번에 재현합니다.

- 돌파 진입, 나눠 사기, 손절, 본전 스톱, 트레일링, 부분 익절
- 오르지 않으면 시간 청산
- 09:47 절반 정리, 09:49:30 잔량 시장가
- 연속 손절 10분 휴식, 세 번째 연속 손절 후 당일 신규 매수 종료
- 하루 손실 한도를 넘기면 보유 종목 정리
- VI 해제 뒤 첫 1분봉이 음봉이면 청산, 해제 직후 신규 매수 거절

로그는 `%USERPROFILE%\.daytrading\logs\` 아래 시각 폴더에 쌓입니다. `fills.csv` 가 체결이고, 그때의 기준 가격(`trigger_price`)과 슬리피지(`slippage_krw`)도 같이 남습니다. `summary.txt` 가 손익 요약입니다. 엑셀에서 한글이 깨지지 않게 저장합니다. 시뮬 시세는 전일종가 대비 ±30%와 호가 단위 밖으로 나가지 않습니다.

호가 방향(매수 잔량이 많은지, 매도 잔량이 많은지)은 기록만 하고 매수 조건으로 쓰지 않습니다. 매수 잔량/매도 잔량이 5배를 넘으면 그 종목은 제외합니다.

## 아직 키움 문서만으로는 확인되지 않은 것

공식 예제와 같은 값만 주문·시세 코드에 넣었습니다. 예제에 없는 것은 추측해서 쓰지 않았습니다.

- VI 실시간(1h)의 발동 구분(9068) 값 표가 예제에 없습니다. 지금은 해제 시각(1224)이 있으면 해제로 봅니다.
- 주식기본정보(ka10001)에는 관리·투자주의·경고·위험·단기과열·ETF·상장일 칸이 없습니다. 종목정보 리스트(ka10099, `POST /api/dostk/stkinfo`, `mrkt_tp`)로 채웁니다. 공식 명세 기준입니다.
  - `regDay` → 상장일. `orderWarning` 2 정리매매, 3 단기과열, 4 투자위험. `state` 가 `관리종목` 이면 관리종목.
  - ETF는 `mrkt_tp` 8, ETN은 60·70·90. `orderWarning` 1(ETF투자주의요망)도 ETF로 봅니다.
  - `orderWarning` 5의 공식 문구는 `투자경과` 입니다. 투자경고로 바꾸지 않습니다.
  - 투자주의, 투자경고, 스팩, 우선주 칸은 공식 필드가 없어 `unknown` 입니다. `auditInfo` 예제의 `투자주의환기종목` 은 투자주의로 보지 않습니다.
- 모의투자에서 실시간 조건검색(ka10173)이 되는지는 공식 문서에 없습니다.
- 모의투자 체결가와 슬리피지는 확인하지 못했습니다. 시뮬은 설정한 틱만큼 불리하게 체결합니다.
- 수수료 안내 페이지는 오류로 열리지 않았습니다. 0.015%는 FAQ 기준입니다.
- 명세에 비율이 없는 두 가지는 설정 기본값으로 잡았습니다. 긴 윗꼬리는 1분봉 범위의 50%, 09:47 분할 청산은 수량의 50%입니다. 설정에서 바꿀 수 있습니다.
- 체결 통보(00)의 상태코드(913)와 매도수 구분(907) 값 표는 예제에 없습니다. 체결로 보이는 값만 잔고에 넣고, 대기 중인 주문 방향으로 매수·매도를 가릅니다.
- 체결강도 FID 228이 당일 누적인지는 예제만으로 확인하지 못했습니다. 받은 값을 구간 평균으로 씁니다.
- 분봉이 비어 있는 분은 0으로 채우지 않습니다. 평균은 찍힌 분봉만 사용합니다.

`--check` 로 토큰과 시세 등록을 확인할 수 있습니다. 실제 모의 계좌의 체결 품질은 사용자 키로 `--paper` 를 돌려 봐야 하고, 그 결과만으로 실전 사용을 권하지 않습니다.

## Time Machine 과 주문 승인

이 기능은 09:00~09:50 자동 매매와 따로입니다. `strategy.py`, `session.py`, `execution.py`, `risk.py` 의 기존 한도·시간 규칙은 바꾸지 않았습니다. 게이트를 그 자동 경로에 끼우는 일은 후속입니다.

브로커는 **키움 REST 모의투자**(`https://mockapi.kiwoom.com`)입니다. 지시 원문에 KIS 모의투자가 있었으나, 이 저장소의 명세와 코드가 키움이라 키움을 따릅니다. KIS 어댑터는 넣지 않았습니다.

**시뮬레이션 ≠ 예측.** Time Machine 은 과거 분봉을 재배열해 손절·목표가 먼저 닿는 횟수를 셀 뿐입니다. 수익이나 승률을 약속하지 않습니다. 실주문·결제·실전 주소는 사용하지 않습니다.

키 없이 내장 가짜 분봉으로 돌립니다.

```bat
set PYTHONPATH=src
py -3 -m daytrading --timemachine
```

화면에서는 **Time Machine** 탭의 **샘플 픽스처 실행** 입니다. 장중 루프에서 부르지 않습니다. 결과 JSON 과 화면 예시는 `docs/timemachine-sample.json`, `docs/timemachine-sample.png` 입니다. 설명은 `docs/timemachine.md` 에 있습니다.

| 항목 | 기본 | 출처 |

| 유관기관수수료 | 0 | 계좌·시점마다 달라 숫자를 넣지 않았습니다. |

분봉 TR 은 정규장 [ka11080](https://openapi.kiwoom.com/guide/apiGuideContents/07/ka11080) 입니다. 며칠치를 주는지는 문서에 없습니다. 풀세션이 20개 미만이면 시뮬을 거절합니다.

**주문 승인** 탭은 수동 주문용입니다. 위험 검사 PASS, 그 주문 번호만 「예」, Allow once 또는 Deny. 「항상 허용」은 없습니다. 세 단계 전에는 모의 기록도 남지 않습니다. 청산은 하루 손실 한도로 막지 않으며, 그 판단은 기존 `risk.py` 에 맡깁니다.
